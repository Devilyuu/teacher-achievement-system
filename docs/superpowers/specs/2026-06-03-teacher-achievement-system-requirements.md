# 高校教师个人成果管理系统项目需求说明书

版本：V1.0 初稿  
日期：2026-06-03  
适用阶段：本机/局域网试用版  
参考材料：`浮动绩效积分统计.xlsx`

## 1. 项目背景

高校教师每年在绩效统计、成果评优、年度考核、部门材料汇总等场景中，需要反复提交当年度业绩清单和各类支撑材料。由于不同部门统计口径相近但表格和材料要求略有差异，教师经常需要重复整理、重复上传、重复查找证明材料，管理人员也需要反复催交、核对和汇总。

本项目拟建设一个轻量化的多人登录成果管理系统，帮助教师平时沉淀个人成果和支撑材料，年底或需要上交材料时，一键导出个人业绩清单和按类目整理好的支撑材料压缩包。

## 2. 项目定位

系统定位为：

> 多人登录的轻量教师成果档案与申报材料生成工具。

第一版系统不承担最终审核、最终认定和正式绩效判分职责。系统主要负责成果记录、支撑材料管理、绩效规则提示、基础校验、年度清单生成和材料打包导出。最终审核和分值认定仍在线下完成。

## 3. 建设目标

1. 教师可以随时录入个人成果、过程性工作和支撑材料。
2. 系统沿用现有绩效统计表中的 9 个标准大类和对应小类，并增加受控的自定义兜底类别。
3. 教师年底可以快速生成年度个人业绩清单。
4. 系统可以按年度、大类、小类和成果记录自动整理支撑材料。
5. 管理员可以维护账号、绩效规则和导出模板。
6. 管理员可以查看教师年度材料准备状态，并批量导出汇总材料。
7. 第一版支持本机/局域网部署，便于小范围试用和后续迁移。

## 4. 第一版范围

### 4.1 包含范围

- 多人登录。
- 教师账号管理。
- 教师个人成果管理。
- 过程性工作和成果性工作记录。
- 支撑材料上传与成果绑定。
- 绩效规则提示。
- 教师手动填写申报分。
- 基础校验和缺材料提醒。
- 简单申报状态管理。
- 个人年度申报包导出。
- 管理员年度汇总和批量导出。
- 本机/局域网运行。
- 数据与上传文件本地备份。

### 4.2 暂不包含范围

- 线上正式审核流。
- 多级审批、退回、复核、公示。
- 与学校统一身份认证对接。
- 短信、邮箱验证码、找回密码。
- 复杂自动计分规则引擎。
- 自动识别材料内容。
- 公网云部署。
- 移动端 App。

## 5. 用户角色

### 5.1 教师

教师是系统主要使用者，负责维护自己的成果记录和支撑材料。

主要权限：

- 登录系统。
- 修改个人密码。
- 查看个人成果库。
- 新增、编辑、删除自己的成果记录。
- 上传、删除、替换自己的支撑材料。
- 查看绩效规则提示。
- 填写基本分、绩效分和申报积分。
- 查看年度材料完整性提醒。
- 提交年度材料整理状态。
- 导出个人年度申报包。

### 5.2 团队项目负责人

团队项目负责人可以作为教师角色的扩展权限，不需要单独设置复杂角色。

主要权限：

- 创建团队项目成果。
- 维护团队项目成员。
- 填写成员分配分值或说明。
- 上传团队项目支撑材料。
- 导出团队项目申报表。

### 5.3 管理员

管理员负责系统基础维护和汇总导出。

主要权限：

- 创建、编辑、停用教师账号。
- 通过 Excel 批量导入教师账号。
- 重置教师密码。
- 维护部门、角色和教师基础信息。
- 维护绩效项目大类、小类和规则说明。
- 查看各教师年度申报状态。
- 查看材料缺失情况。
- 导出单个教师或多个教师的年度材料包。
- 导出全体教师年度汇总表。
- 执行系统数据备份。

## 6. 账号与登录需求

第一版不开放教师自助注册。

教师账号由管理员手动创建或通过 Excel 批量导入。建议登录名优先使用工号；如果没有工号，可使用管理员指定账号。

教师账号基础字段：

- 工号/账号
- 姓名
- 所属部门
- 手机号或邮箱，可选
- 角色
- 是否启用
- 初始密码

账号规则：

- 教师首次登录后可以修改密码。
- 教师不能自行修改姓名、工号和部门。
- 管理员可以重置密码。
- 管理员可以停用账号。
- 第一版不提供短信、邮箱验证和自助找回密码。

## 7. 绩效分类需求

系统沿用附件绩效统计表中的 9 个标准大类：

1. 师德师风及党建思政工作
2. 教师发展
3. 教学
4. 产教融合工作
5. 学生工作
6. 科研与社会服务工作
7. 国际交流与合作
8. 育人成效
9. 监管类工作

在 9 个标准大类之外，系统增加一个受控兜底类别：

10. 其他有价值工作（自定义）

该类别用于记录现有绩效分类暂未覆盖、但教师认为有必要申报或留痕的工作。例如在江苏省职业技能大赛中担任裁判、担任校外专家评审、参与临时专项支持、承担无法归入既有小类但具有工作价值的事项。

自定义类别使用要求：

- 教师选择该类别后，项目小类默认为“自定义工作事项”。
- 教师必须填写工作类型、工作内容、价值说明和支撑材料。
- 系统不自动判断是否赋分，只进入清单和材料包。
- 最终是否认定和赋分仍以线下审核为准。
- 管理员后续可根据使用情况，将高频自定义事项沉淀为正式小类。

每个标准大类下维护对应小类。小类来源于现有 Excel 表中的字段和积分规则。

绩效规则字段建议包括：

- 大类
- 小类
- 基本分规则
- 国家级绩效分规则
- 省级绩效分规则
- 市级绩效分规则
- 校级绩效分规则
- 学院级绩效分规则
- 是否团队项目
- 是否部门/负责人赋分
- 是否需要个人申报
- 封顶说明
- 特殊说明
- 是否启用

## 8. 成果记录需求

### 8.1 成果记录类型

过程性工作不单独设置大类，而是作为每条成果记录的申报性质。

申报性质包括：

- 过程性工作：已有执行过程、阶段材料，但尚未形成最终成果。
- 成果性工作：已经形成获奖、立项、结项、发表、授权、到账等明确成果。

后续可根据需要增加“持续性工作”，但第一版可先用过程性工作和成果性工作覆盖。

### 8.2 成果记录字段

每条成果记录建议包含：

- 年度
- 项目大类
- 项目小类
- 申报性质
- 项目具体名称
- 成果日期或起止时间
- 成果级别
- 本人角色
- 是否团队项目
- 团队项目名称，可选
- 基本分
- 绩效分
- 申报积分
- 规则提示
- 当前阶段，适用于过程性工作
- 备注
- 记录状态
- 创建时间
- 更新时间

### 8.3 申报分填写

第一版采用“规则提示 + 教师手动填写申报分”的方式。

系统展示该小类对应的积分规则和备注说明，教师根据规则自行填写基本分、绩效分和申报积分。系统不承担最终自动计分职责，最终分值以线下审核结果为准。

系统可提供基础校验：

- 必填项是否完整。
- 是否上传支撑材料。
- 申报分是否为空。
- 申报分是否明显异常。
- 是否超过规则中明确的封顶说明。
- 团队项目是否填写成员或分配说明。
- 过程性工作是否上传过程材料。

## 9. 支撑材料需求

支撑材料必须绑定到具体成果记录，不设置无归属的公共文件库。

每条成果可以上传多个支撑材料。

支持文件类型：

- PDF
- Word
- Excel
- 图片
- 压缩包
- 其他管理员允许的常见文件类型

材料字段：

- 材料编号
- 所属成果记录
- 材料名称
- 材料说明
- 原始文件名
- 文件类型
- 文件大小
- 上传人
- 上传时间
- 存储路径

材料编号由系统自动生成，并在申报清单、材料目录和 ZIP 文件名中保持一致。

如果某条成果没有上传支撑材料，系统应标记为“缺少材料”。

## 10. 状态管理需求

第一版仅提供轻量状态，不做线上审核。

### 10.1 单条成果状态

- 草稿：刚录入，尚未补全。
- 待完善：缺必填信息或缺支撑材料。
- 可申报：信息和材料基本完整。
- 已纳入导出：本年度导出时已选择该成果。

### 10.2 年度申报状态

- 未开始：该教师该年度还没有成果记录。
- 整理中：已有成果记录，但教师尚未确认提交。
- 已提交：教师确认本年度材料已整理完成。
- 已导出：系统已经生成过该教师年度材料包。

状态仅用于提醒、筛选和导出管理，不代表最终审核结论。

## 11. 导出需求

### 11.1 个人年度申报包

教师可以选择年度后导出个人年度申报包。

个人年度申报包建议包括：

- 个人项目申报表 Excel
- 团队项目申报表 Excel，如有
- 年度积分汇总表 Excel
- 材料目录 Excel
- 支撑材料 ZIP

个人项目申报表建议字段：

- 序号
- 项目大类
- 项目小类
- 申报性质
- 项目具体名称
- 成果日期/周期
- 级别
- 本人角色
- 基本分
- 绩效分
- 申报积分
- 支撑材料编号+名称
- 材料状态
- 备注

### 11.2 材料目录

材料目录建议字段：

- 材料编号
- 对应成果序号
- 项目大类
- 项目小类
- 项目名称
- 申报性质
- 材料名称
- 文件名
- 文件类型
- 上传时间

### 11.3 ZIP 包结构

个人年度申报包 ZIP 结构建议如下：

```text
2026年度绩效申报材料_张三.zip
├─ 01_个人项目申报表.xlsx
├─ 02_团队项目申报表.xlsx
├─ 03_年度积分汇总表.xlsx
├─ 04_材料目录.xlsx
└─ 05_支撑材料/
   ├─ 01_师德师风及党建思政工作/
   ├─ 02_教师发展/
   ├─ 03_教学/
   ├─ 04_产教融合工作/
   ├─ 05_学生工作/
   ├─ 06_科研与社会服务工作/
   ├─ 07_国际交流与合作/
   ├─ 08_育人成效/
   ├─ 09_监管类工作/
   └─ 10_其他有价值工作（自定义）/
```

材料文件命名建议：

```text
成果序号_申报性质_项目小类_材料说明.扩展名
```

示例：

```text
003_过程性工作_精品在线开放课程建设_课程平台截图.pdf
004_成果性工作_教学能力比赛_获奖证书.jpg
```

### 11.4 管理员汇总导出

管理员可以按年度、部门、教师和申报状态筛选后导出：

- 全体教师年度积分汇总表
- 单个教师年度申报包
- 多个教师年度申报包
- 按教师分包的批量 ZIP
- 材料缺失统计表

管理员界面至少包含：

4. 年度申报状态查看
5. 材料缺失统计

绩效规则管理应支持：

- 编辑分值说明。
- 设置是否团队项目。

## 13. 本机/局域网部署需求

第一版采用本机/局域网试用部署。

部署方式：

- 一台电脑作为主机。
- 主机运行 Web 服务和数据库。
- 局域网内教师通过浏览器访问。
- 访问地址类似 `http://主机IP:端口`。
- 数据库和上传材料保存在主机本地。

部署要求：

- 不依赖公网。
- 不需要教师安装客户端。
- 主机管理员可以启动和停止服务。
- 支持本地数据备份。
- 后续具备迁移到正式服务器的可能。

## 14. 数据存储与备份需求

第一版建议使用轻量数据库和本地文件存储。

数据存储内容：

- 用户账号
- 部门信息
- 绩效规则
- 成果记录
- 支撑材料元数据
- 年度申报状态
- 导出记录

文件存储内容：

- 教师上传的支撑材料
- 系统生成的导出文件
- 备份文件

建议文件目录结构：

```text
data/
├─ database/
├─ uploads/
│  └─ 年度/教师ID/成果ID/
├─ exports/
│  └─ 年度/教师ID/
└─ backups/
```

备份需求：

- 管理员可一键生成系统备份。
- 备份内容包括数据库和上传材料。
- 支持下载备份包。
- 支持在必要时恢复备份。

## 15. 非功能需求

### 15.1 易用性

- 教师填报页面应尽量简单。
- 大类和小类使用下拉选择。
- 选择小类后自动显示规则提示。
- 上传材料应支持一次选择多个文件。
- 年度清单页面应清楚显示缺材料、缺分值、可申报状态。

### 15.2 性能

- 支持学院或部门级别试用。
- 第一版建议支持 50-200 名教师使用。
- 支持常规文件上传和 ZIP 打包下载。

### 15.3 安全

- 必须登录后使用。
- 教师只能查看和管理自己的成果。
- 管理员可以查看和导出全部数据。
- 密码需加密存储。
- 上传文件应限制大小和类型。

### 15.4 可维护性

- 绩效规则应由管理员可配置。
- 导出模板应尽量可维护。
- 数据结构应支持后续迁移到正式服务器。

## 18. 当前已确认结论

1. 系统从单用户工具升级为多人登录系统。
2. 第一版先做本机/局域网试用版。
3. 不做线上正式审核，线下审核即可。
4. 过程性工作融入现有 9 大类和小类，不单独设大类。
5. 每条成果记录增加申报性质。
6. 第一版采用规则提示和教师手动填写申报分。
7. 教师账号由管理员手动创建或 Excel 批量导入。
8. 支撑材料必须绑定具体成果记录。
9. 导出格式可在现有 Excel 附表基础上增加必要字段。
10. 系统设置简单状态用于提醒、筛选和导出。
11. 标准 9 大类之外增加“其他有价值工作（自定义）”兜底类别，用于记录无法归入现有分类但有必要申报的工作。

## 19. 待进一步确认事项

1. 是否需要在第一版支持教师批量导入个人成果。
2. 上传文件大小上限。
3. 是否需要支持图片预览和 PDF 在线预览。
4. 是否需要管理员修改教师已填成果。
5. 第一版是否需要内置附件中的绩效规则，还是允许管理员导入规则表。
6. 导出 Excel 是否需要严格保留原表样式。
7. 是否需要记录每次导出的历史版本。
