# 绩效规则维护设计

日期：2026-06-15

## 目标

管理员可以维护填报规则目录，包括新增、编辑、启用、停用和排序。规则仅用于填报提示，最终认定仍在线下完成。

## 启动同步修正

当前启动逻辑会覆盖数据库中的规则内容，并停用不在内置 JSON 中的规则，这与人工维护冲突。

调整后：

- 内置目录只负责补充数据库中不存在的初始规则。
- 已存在规则的人工修改、启停状态和排序不会被启动过程覆盖。
- 管理员新增规则不会因为不在内置目录中而被停用。

## 页面与操作

规则列表展示全部规则，可按状态和关键词筛选。每行显示：

- 大类和小类
- 基本分与五级规则
- 赋分方式
- 状态
- 排序值
- 编辑和启停操作

新增和编辑使用独立表单页，字段包括：

- 大类、小类
- 基本分
- 国家级、省级、市级、校级、学院级规则
- 赋分方式：个人申报、团队负责人申报并分配、项目负责人统一赋分
- 备注
- 排序值
- 是否启用

大类和小类组合必须唯一。规则不提供物理删除，避免误删规则目录。

## 数据行为

- 停用规则不会出现在教师新增填报和成果筛选选项中。
- 已有成果仍保留原有大类和小类文字，不随规则编辑自动迁移。
- 修改规则名称可能导致历史成果不再匹配规则提示，表单页明确提醒管理员。
- 排序按 `sort_order`、数据库 ID 依次排列。

## 权限与错误

- 仅管理员可以访问和修改规则。
- 重复大类与小类组合返回页面错误，不产生重复记录。
- 无效赋分方式和非整数排序值由表单校验拒绝。
- 当前启用规则可以停用，停用规则可以重新启用。

## 测试

- 人工修改和新增规则在再次执行启动同步后保持不变。
- 新增、编辑、启停和排序正确。
- 重复规则被拒绝。
- 普通教师不能访问维护接口。
- 停用规则不进入教师填报选项，重新启用后恢复。
- 桌面和手机端表单、列表无页面级横向溢出。
