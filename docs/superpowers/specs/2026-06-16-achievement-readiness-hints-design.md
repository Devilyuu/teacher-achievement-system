# 成果详情待完善原因提示设计说明

## 背景

年度首页已经可以把当前年度的“待完善”成果集中列出来，并显示主要缺失原因。老师点击其中一条成果进入详情页后，还需要在当前成果页面继续看到“这条具体差什么”，否则会出现从首页知道有问题、进入详情后又要自己判断的问题。

## 目标

- 在成果详情页显示当前成果的待完善原因。
- 原因继续复用 `app/services/achievement_readiness.py` 中的 `missing_reasons`，确保首页、详情页、管理员导出三处口径一致。
- 提示只用于教师自查，不作为线上审核意见。
- 给出直接操作入口：需要补字段时去编辑成果，需要补材料时在本页上传材料。
- 编辑页在编辑已有成果时显示紧凑提示，提醒保存后系统会重新判断状态。

## 范围

本次包含：

- 成果详情页在“申报信息”上方展示“待完善原因”提示卡。
- 仅当当前成果状态为“待完善”且存在缺失原因时展示。
- 提示卡展示原因列表，并提供“编辑成果”入口。
- 如果原因包含材料相关问题，提示用户可在本页“支撑材料”区域上传或替换材料。
- 编辑页仅在编辑已有成果且存在缺失原因时展示一条轻量提示。

本次不包含：

- 不新增审核意见、退回意见、线上审批流。
- 不新增用户手动勾选完成项。
- 不改变成果状态计算规则。
- 不新增消息提醒或通知。

## 页面设计

详情页：

- 位置：详情主栏顶部，位于“申报信息”卡片之前。
- 样式：沿用浅色面板、橙黄色提醒色、lucide 图标，和年度首页“待处理事项”保持同一视觉语言。
- 内容：
  - 标题：`待完善原因`
  - 说明：`以下为系统根据当前填报信息自动生成的自查提示，不代表线下审核意见。`
  - 列表：逐条显示缺失原因。
  - 操作：`编辑成果`按钮。
  - 如果包含材料问题，显示一句 `材料可在下方支撑材料区域上传、替换或重命名。`

编辑页：

- 位置：表单第一张“成果信息”卡片之前。
- 样式：紧凑提醒条，不占用太多页面高度。
- 内容：展示缺失原因列表，并提示保存后系统会重新判断状态。

## 数据设计

`app/routers/achievements.py`：

- 导入 `missing_reasons`。
- 在详情页上下文中传入 `readiness_reasons`。
- 在编辑表单上下文中传入 `readiness_reasons`。

模板：

- `app/templates/achievements/detail.html` 读取 `readiness_reasons`。
- `app/templates/achievements/form.html` 读取 `readiness_reasons`。

样式：

- 在 `app/static/app.css` 增加 `.readiness-panel`、`.readiness-list`、`.readiness-inline` 等轻量样式。

## 测试设计

- 详情页对待完善成果展示缺失原因和“编辑成果”入口。
- 详情页对可申报成果不展示待完善原因卡片。
- 编辑页对待完善成果展示缺失原因提示。
- CSS 中存在待完善原因提示组件样式。

## 验收标准

- 从年度首页点击待处理成果进入详情页后，可以直接看到待完善原因。
- 同一条成果在详情页显示的原因与首页、管理员导出使用同一套判断逻辑。
- 点击“编辑成果”能进入编辑页面。
- 可申报成果详情页不显示待完善原因提示。
- 自动化测试通过。
