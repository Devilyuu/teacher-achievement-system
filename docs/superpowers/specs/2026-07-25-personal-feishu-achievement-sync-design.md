# 个人成果智能录入与飞书同步设计

## 1. 背景与目标

在现有教师成果管理平台中，为指定教师账号增加个人专用的“智能快速记录”功能。教师可以输入自然语言，或在满足浏览器安全条件时使用语音描述一项成果。系统将描述整理为结构化成果草稿，由教师确认后保存到本系统，并单向同步到指定飞书多维表格。

本功能仅供一个已配置的教师账号使用。其他教师不显示智能录入和飞书同步入口，也不会接触该教师的飞书配置或同步记录。

第一版目标：

- 在现有成果新增流程中提供自然语言快速录入。
- 识别并预填年度、成果名称、分类、级别、角色、状态和积分建议。
- 教师确认后再保存，避免错误分类直接进入成果库。
- 本系统保存成功后，将成果元数据同步到指定飞书多维表格。
- 飞书不可用时保留本系统数据，并允许重试。
- 不自动触发现有飞书到 Obsidian 的后续同步。

第一版不包含：

- 为其他教师绑定飞书表格。
- 从飞书反向修改本系统成果。
- 自动将支撑材料文件上传到飞书附件字段。
- 无人工确认的全自动成果入库和积分认定。
- 飞书机器人或飞书内聊天录入。

## 2. 已确认的飞书结构

目标资源为知识库中的多维表格，包含一张年度教科研业绩数据表。现有字段共 22 个，主要字段包括：

- 成果名称
- 成果年度
- 成果大类
- 成果细类
- 级别
- 本人角色
- 状态
- 备注
- 支撑材料
- 确认同步
- 同步状态
- 同步说明

飞书中的成果大类为 9 类，与本系统分类体系可以建立稳定映射。该表已有 Obsidian 同步痕迹，因此本平台不得修改已有记录的 Obsidian 同步状态，也不得依靠成果名称作为唯一标识。

需要在飞书表中增加一个文本字段：

- `成果平台ID`：保存本系统成果主键，用于新增、更新和防重复。

## 3. 用户体验

### 3.1 入口

在现有“新增成果”页面最上方增加“智能快速记录”区域，仅对已配置的个人账号显示。

区域包含：

- 多行文字输入框。
- “识别并预填”按钮。
- 麦克风按钮；仅在浏览器支持且页面处于安全上下文时显示为可用。
- 最近一次识别状态和错误提示。

原有结构化表单继续保留。智能录入只是预填工具，不替代手工填报。

### 3.2 操作流程

1. 教师输入或口述一段成果描述。
2. 语音输入先转成文字，文字直接进入字段识别。
3. 系统输出结构化草稿并填入现有成果表单。
4. 分类、积分或日期存在不确定性时，在对应字段旁显示“请确认”。
5. 教师检查并修改字段。
6. 教师提交现有成果表单。
7. 本系统完成数据库保存后，立即尝试同步飞书。
8. 成果详情页显示飞书同步状态和“重新同步”操作。

系统不会在教师确认表单前写入本系统或飞书。

## 4. 字段识别

智能识别输出固定的结构化对象，包含：

- `year`
- `title`
- `category`
- `subcategory`
- `claim_nature`
- `date_range`
- `level`
- `personal_role`
- `current_stage`
- `base_score`
- `performance_score`
- `claimed_score`
- `notes`
- `confidence`
- `uncertain_fields`

处理原则：

- 分类必须限定在本系统现有规则目录内，不允许模型创建新的正式分类。
- 无法确定的小类使用“其他成果”或保留待确认状态，不强行猜测。
- 基本分和绩效分只给出建议，教师仍可修改，线下审核规则保持不变。
- 模型输出必须经过服务端结构校验，不能直接作为数据库参数使用。
- 原始描述保留在当前请求或必要的审计字段中，不作为公开页面内容。

智能识别服务通过独立适配器调用，避免业务代码绑定某一家模型供应商。第一版优先选择在国内网络可稳定访问、支持结构化 JSON 输出的服务。

## 5. 语音输入

浏览器使用 `MediaRecorder` 录制短语音，音频发送到本系统服务端，再由腾讯云语音识别转换为文字。

限制与降级：

- 远程浏览器麦克风要求 HTTPS。
- 当前 HTTP 公网访问环境下，文字智能录入正常使用，语音入口显示“需启用 HTTPS”。
- 本机 `localhost` 环境可用于语音开发测试。
- 教师拒绝麦克风权限、浏览器不支持录音或识别失败时，页面保留文字输入方式。
- 第一版限制单段录音时长和文件大小，避免长音频占用服务器资源。

音频只用于本次识别。识别完成或失败后不长期保存原始录音。

## 6. 飞书同步

### 6.1 调用身份

CLI 用户登录只用于开发阶段的只读结构检查，不作为生产系统凭证。

生产系统使用飞书企业自建应用的应用身份：

- 服务端获取并缓存 `tenant_access_token`。
- 应用开通多维表格记录读取、新增和更新权限。
- 应用被授予目标多维表格的必要访问权限。
- App ID、App Secret、目标多维表格标识和启用用户标识只保存在服务器环境变量中。
- 所有飞书请求由服务端发起，浏览器不接触飞书凭证。

### 6.2 字段映射

| 本系统字段 | 飞书字段 | 规则 |
| --- | --- | --- |
| `achievement.id` | 成果平台ID | 字符串，唯一去重键 |
| `title` | 成果名称 | 直接写入 |
| `year` | 成果年度 | 转换为飞书已有选项 |
| `category` | 成果大类 | 通过固定映射表写入 |
| `subcategory` | 成果细类 | 通过固定映射表写入；无匹配时写“其他” |
| `level` | 级别 | 直接写入 |
| `personal_role` | 本人角色 | 直接写入 |
| `status` | 状态 | 转换为可读状态文本 |
| `notes`、`current_stage` | 备注 | 合并非空内容 |
| 固定值 | 确认同步 | `false` |
| 固定值 | 同步状态 | `待确认` |
| 固定值 | 同步说明 | `由教师成果库自动写入，待确认后进入 Obsidian` |

第一版不写入“支撑材料”附件字段，避免文件上传失败影响成果元数据同步。

### 6.3 新增与更新

同步前按“成果平台ID”查询飞书记录：

- 没有匹配记录：新增。
- 有且仅有一个匹配记录：更新平台负责的字段。
- 出现多个匹配记录：停止自动更新，标记冲突并提示人工处理。

平台不得覆盖以下由飞书或 Obsidian 管理的字段：

- 确认同步已被人工勾选后的状态。
- 已被 Obsidian 修改的同步状态和同步说明。
- 关键词、可用于、Obsidian 链接和其他不属于本系统的字段。

当已有记录已进入 Obsidian 流程时，平台只更新成果基础字段，不把“确认同步”重置为未勾选。

## 7. 本系统数据变化

为成果增加飞书同步元数据，或建立一张一对一同步记录表。推荐使用独立同步记录表，以隔离外部系统状态：

- `achievement_id`
- `feishu_record_id`
- `sync_status`：`pending`、`synced`、`failed`、`conflict`
- `last_synced_at`
- `last_error`
- `payload_hash`
- `created_at`
- `updated_at`

`achievement_id` 唯一，确保一项成果只对应一条同步状态记录。

`payload_hash` 用于判断平台负责的字段是否发生变化，避免无意义的重复更新。

## 8. 失败处理

保存顺序固定为“本系统优先，飞书随后”：

1. 先提交本系统数据库事务。
2. 创建或更新待同步记录。
3. 尝试调用飞书。
4. 成功后记录飞书记录 ID 和同步时间。
5. 失败时记录错误摘要，不回滚本系统成果。

成果详情页显示：

- 已同步
- 待同步
- 同步失败
- 数据冲突

失败状态提供“重新同步”按钮。鉴权失败、权限不足、字段不匹配和网络错误使用不同的用户提示；详细响应只记录在服务端日志，不向教师暴露凭证或内部请求信息。

第一版用户量和同步量很小，不引入 Celery、Redis 等队列。采用保存后即时同步加手工重试，后续有需要再增加定时补偿任务。

## 9. 权限与安全

- 飞书入口只对服务器配置的指定用户显示。
- 服务端接口再次校验当前用户，不能只依赖前端隐藏。
- App Secret、语音识别密钥和模型密钥不得进入 Git、HTML、JavaScript或日志。
- 所有外部请求设置连接和响应超时。
- 日志只记录成果 ID、同步阶段、飞书错误码和请求追踪标识。
- 语音文件使用临时存储并在识别后删除。
- 对智能识别接口增加录音大小、文字长度和调用频率限制。

## 10. 测试与验收

### 10.1 自动测试

- 非指定教师看不到入口，调用接口返回无权限。
- 文字描述可以生成结构合法的表单草稿。
- 无效模型输出不能写入表单或数据库。
- 教师提交前不会产生成果或飞书记录。
- 本系统保存成功、飞书失败时成果仍然存在。
- 同一成果重复同步会更新原飞书记录，不新增重复记录。
- 飞书出现重复“成果平台ID”时进入冲突状态。
- 已勾选“确认同步”的飞书记录不会被重置。
- 同步请求不包含支撑材料文件。
- 未启用 HTTPS 时文字录入可用，语音入口正确降级。

### 10.2 联调验收

使用一项测试成果完成以下检查：

1. 输入自然语言并核对预填字段。
2. 修改一个识别字段并提交。
3. 确认本系统成果详情保存正确。
4. 确认飞书新增一条记录且字段映射正确。
5. 确认“确认同步”未勾选，“同步状态”为“待确认”。
6. 修改本系统成果并重新同步，确认飞书更新原记录。
7. 模拟飞书不可用，确认本系统保存成功且可手工重试。

## 11. 实施顺序

1. 配置飞书自建应用权限，并在目标表新增“成果平台ID”字段。
2. 实现个人账号开关、同步记录表和飞书客户端。
3. 完成成果保存后的飞书新增、更新、状态显示和重试。
4. 增加文字智能识别和现有表单预填。
5. 配置 HTTPS 后增加语音录制与腾讯云语音识别。

这个顺序先跑通可靠的数据同步，再增加智能输入和语音，便于分别验证和定位问题。
